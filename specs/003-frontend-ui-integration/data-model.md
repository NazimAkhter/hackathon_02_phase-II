# Data Model: Frontend Interface & Integration

**Feature**: 003-frontend-ui-integration
**Date**: 2026-01-19
**Scope**: Frontend data structures, state management entities, and form schemas

---

## Overview

This document defines all data entities managed by the frontend application. These entities represent:
1. **Domain Entities**: Data structures matching backend API responses (Task, User)
2. **Session State**: Authentication and runtime state (AuthContext, TaskContext)
3. **Form State**: Input validation and submission data
4. **UI State**: Loading indicators, error messages, and user interactions

---

## 1. Domain Entities (Backend Contract)

### 1.1 Task Entity

Represents a single todo item in the user's task list. Matches backend API response from Spec 2.

```typescript
// types/task.ts
export interface Task {
  id: string                    // UUID from backend
  user_id: string               // Owner user ID (from JWT token)
  title: string                 // Task description (1-500 characters)
  completed: boolean            // Completion status
  created_at: string            // ISO 8601 timestamp (e.g., "2026-01-19T10:30:00Z")
  updated_at: string            // ISO 8601 timestamp
}
```

**Field Constraints**:
- `id`: UUID v4 format, generated by backend
- `user_id`: UUID v4, extracted from JWT token
- `title`: 1-500 characters (validated by backend and frontend)
- `completed`: boolean, defaults to `false` on creation
- `created_at`: ISO 8601 string, set by backend on creation
- `updated_at`: ISO 8601 string, auto-updated by backend on modification

**Usage**:
- Task list display (FR-006, FR-007)
- Task creation response (FR-014)
- Task update operations (FR-018, FR-023)
- Task deletion (FR-027)

---

### 1.2 User Entity

Represents authenticated user information. Derived from JWT token payload and Better Auth session.

```typescript
// types/user.ts
export interface User {
  id: string                    // User UUID from JWT token
  email: string                 // User email address
  created_at?: string           // Optional: account creation timestamp
}
```

**Field Constraints**:
- `id`: UUID v4 from JWT payload (`userId` field)
- `email`: Valid email format (validated during signup)
- `created_at`: Optional field, may not be included in JWT payload

**Usage**:
- Display user info in header (FR-005)
- API endpoint construction (`/api/{user_id}/tasks`)
- Authorization checks (ensure user_id matches JWT payload)

---

### 1.3 JWT Session

Represents the decoded JWT token payload from Better Auth. Used for authentication and authorization.

```typescript
// types/user.ts
export interface JWTPayload {
  userId: string                // User UUID
  email: string                 // User email
  iat: number                   // Issued at (Unix timestamp)
  exp: number                   // Expiration (Unix timestamp, 7 days from iat)
}
```

**Field Constraints**:
- `userId`: UUID v4
- `email`: Valid email address
- `iat`: Unix timestamp (seconds since epoch)
- `exp`: Unix timestamp, 7 days after `iat` (604800 seconds)

**Usage**:
- Extract user ID for API calls
- Check token expiration
- Display user email in UI
- Authorization header: `Bearer <encoded_jwt>`

## 2. Session State (React Context)

### 2.1 Auth Context State

Manages authentication state across the application.

```typescript
// components/auth/AuthProvider.tsx
export interface AuthContextType {
  // User state
  user: User | null                           // Current authenticated user or null
  isAuthenticated: boolean                    // Computed: !!user
  isLoading: boolean                          // Loading state during initial auth check

  // Auth operations
  login: (email: string, password: string) => Promise<void>
  signup: (email: string, password: string) => Promise<void>
  logout: () => Promise<void>

  // API client
  apiClient: APIClient                        // Configured API client with JWT injection
}
```

**State Transitions**:
1. **Initial Load**: `isLoading = true`, `user = null`
2. **Authenticated**: `isLoading = false`, `user = { id, email }`, `isAuthenticated = true`
3. **Unauthenticated**: `isLoading = false`, `user = null`, `isAuthenticated = false`
4. **Logout**: Transition from authenticated → unauthenticated, redirect to `/login`

**Usage**:
- Protected routes check `isAuthenticated` before rendering (FR-001)
- API calls use `apiClient` with automatic JWT injection (FR-002)
- Login/signup pages call `login` / `signup` functions
- Header displays `user.email` and provides logout button (FR-005, FR-042)

### 2.2 Task Context State

Manages task list state and CRUD operations.

```typescript
// context/TaskContext.tsx (if using separate context)
export interface TaskContextType {
  // Task list state
  tasks: Task[]                               // Array of user's tasks
  isLoading: boolean                          // Loading state for fetch operations
  error: string | null                        // Error message or null

  // CRUD operations
  fetchTasks: () => Promise<void>             // Load all tasks
  createTask: (title: string) => Promise<Task>
  updateTask: (taskId: string, updates: Partial<Task>) => Promise<Task>
  toggleTaskCompletion: (taskId: string) => Promise<Task>
  deleteTask: (taskId: string) => Promise<void>

  // UI state helpers
  clearError: () => void
}
```

**Alternative: Hook-Based Approach (Simpler)**:
Instead of separate TaskContext, use `useTasks` hook in components that need task state:

```typescript
// hooks/useTasks.ts
export function useTasks() {
  const { user, apiClient } = useAuth()
  const [tasks, setTasks] = useState<Task[]>([])
  const [isLoading, setIsLoading] = useState(false)
  const [error, setError] = useState<string | null>(null)

  // CRUD operations implementation...

  return { tasks, isLoading, error, fetchTasks, createTask, updateTask, toggleTaskCompletion, deleteTask }
}
```

**Decision**: Use hook-based approach for simplicity. TaskContext not needed unless sharing state across many components.

## 6. Type Guards and Utilities

### 6.1 Type Guard for Task

```typescript
// types/task.ts
export function isTask(obj: any): obj is Task {
  return (
    typeof obj === 'object' &&
    typeof obj.id === 'string' &&
    typeof obj.user_id === 'string' &&
    typeof obj.title === 'string' &&
    typeof obj.completed === 'boolean' &&
    typeof obj.created_at === 'string' &&
    typeof obj.updated_at === 'string'
  )
}
```

**Usage**: Validate API responses at runtime

---

### 6.2 Date Formatting Utility

```typescript
// lib/utils/formatting.ts
export function formatTimestamp(isoString: string): string {
  const date = new Date(isoString)
  const now = new Date()
  const diffMs = now.getTime() - date.getTime()
  const diffMins = Math.floor(diffMs / 60000)
  const diffHours = Math.floor(diffMs / 3600000)
  const diffDays = Math.floor(diffMs / 86400000)

  if (diffMins < 1) return 'Just now'
  if (diffMins < 60) return `${diffMins}m ago`
  if (diffHours < 24) return `${diffHours}h ago`
  if (diffDays < 7) return `${diffDays}d ago`

  return date.toLocaleDateString()
}
```

**Usage**: Display `created_at` / `updated_at` in human-readable format (optional, not in requirements)

## 7. State Management Architecture

### Option A: Hook-Based (RECOMMENDED)

```
┌─────────────────────────────────────────────────┐
│ AuthContext (Context API)                      │
│  - user: User | null                            │
│  - isAuthenticated: boolean                     │
│  - apiClient: APIClient                         │
│  - login/signup/logout functions                │
└─────────────────────────────────────────────────┘
                    ▲
                    │ useAuth()
                    │
┌─────────────────────────────────────────────────┐
│ Components (pages & components)                 │
│  - Dashboard, TaskList, TaskItem, etc.          │
│  - Use useTasks() hook for task state           │
│  - Component-level state for loading/errors     │
└─────────────────────────────────────────────────┘
```

**Rationale**: Simple, minimal prop drilling, easy to test, good performance

---

### Option B: Multi-Context (Alternative)

```
┌─────────────────────────────────────────────────┐
│ AuthContext                                     │
└─────────────────────────────────────────────────┘
        ▲
        │ useAuth()
        │
┌─────────────────────────────────────────────────┐
│ TaskContext                                     │
│  - tasks: Task[]                                │
│  - CRUD operations                              │
└─────────────────────────────────────────────────┘
        ▲
        │ useTasks()
        │
┌─────────────────────────────────────────────────┐
│ Components                                      │
└─────────────────────────────────────────────────┘
```

**When to use**: If task state needs to be shared across many distant components (not the case here)

## 8. Data Flow Examples

### 8.1 Task Creation Flow

```
User Input (TaskCreateForm)
  ↓ handleSubmit(title)
Component calls createTask(title)
  ↓
API Client: POST /api/{user_id}/tasks with {title}
  ↓ Authorization: Bearer <jwt>
Backend validates JWT, creates task in database
  ↓ 201 Created
Backend returns Task object
  ↓
Component updates local state: setTasks([newTask, ...tasks])
  ↓
UI re-renders with new task at top of list
```

---

### 8.2 Token Expiration Flow

```
User action triggers API call
  ↓
API Client: GET /api/{user_id}/tasks
  ↓ Authorization: Bearer <expired_jwt>
Backend validates JWT → token expired
  ↓ 401 Unauthorized
API Client catches 401 error
  ↓
API Client calls logout()
  ↓
AuthContext clears user state, redirects to /login?redirect=/dashboard
  ↓
User sees login page with message "Session expired. Please log in again."
```
