# Data Model: Backend API & Database Layer

**Feature**: Backend API & Database Layer
**Branch**: `002-backend-api-db`
**Date**: 2026-01-19

## Overview

This document defines the database schema and SQLModel models for the backend API. The data model implements multi-user task storage with referential integrity and user isolation.

## Entity Relationship Diagram

```
┌─────────────────────────────────────┐
│ users (From Spec 1 - Reference Only)│
├─────────────────────────────────────┤
│ id (UUID, PK)                       │
│ email (VARCHAR, UNIQUE)             │
│ password_hash (VARCHAR)             │
│ created_at (TIMESTAMP)              │
│ updated_at (TIMESTAMP)              │
└─────────────────────────────────────┘
           │
           │ 1:N (One user has many tasks)
           │
           ▼
┌─────────────────────────────────────┐
│ tasks (Owned by Backend)            │
├─────────────────────────────────────┤
│ id (INTEGER, PK, AUTO_INCREMENT)    │
│ user_id (UUID, FK → users.id)       │◄─ Foreign Key
│ title (VARCHAR(500), NOT NULL)      │
│ completed (BOOLEAN, DEFAULT FALSE)  │
│ created_at (TIMESTAMP)              │
│ updated_at (TIMESTAMP)              │
└─────────────────────────────────────┘
         Indexes:
         - PRIMARY KEY (id)
         - INDEX (user_id)
         - INDEX (user_id, created_at) for sorted queries
```

**Key Relationships**:
- **One-to-Many**: One user can have many tasks
- **Foreign Key Constraint**: `tasks.user_id` references `users.id`
- **Cascade Delete**: When user deleted, all their tasks are deleted (ON DELETE CASCADE)
- **User Isolation**: All task queries MUST filter by `user_id` from authenticated JWT token

## Entity 1: User (Reference from Spec 1)

**Purpose**: Represents an authenticated user. This table is created and managed by Spec 1 (frontend authentication system). Backend only references it via foreign key.

**Source**: Spec 1 Authentication & User Management

**SQLModel Schema** (Reference - NOT created by backend):
```python
from sqlmodel import SQLModel, Field
from datetime import datetime
from typing import Optional

class User(SQLModel, table=True):
    """
    User model from Spec 1 (Better Auth).
    Backend DOES NOT create or modify this table.
    Only referenced via foreign key in Task model.
    """
    __tablename__ = "users"

    id: str = Field(primary_key=True)  # UUID from Better Auth
    email: str = Field(unique=True, index=True)
    password_hash: str
    created_at: datetime = Field(default_factory=datetime.utcnow)
    updated_at: datetime = Field(default_factory=datetime.utcnow)
```

**Database Table**:
```sql
-- Created by Spec 1 frontend authentication system
-- Backend assumes this table exists

CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_users_email ON users(email);
```

**Attributes**:
- `id` (UUID): Primary key, generated by Better Auth when user signs up
- `email` (VARCHAR(255)): User's email address, unique across system
- `password_hash` (VARCHAR(255)): bcrypt-hashed password (managed by Spec 1)
- `created_at` (TIMESTAMP): User registration timestamp
- `updated_at` (TIMESTAMP): Last profile update timestamp

**Backend Usage**:
- Backend **READS** user_id from JWT token payload
- Backend **DOES NOT** create, update, or delete users
- Backend **REFERENCES** users.id as foreign key in tasks table
- Backend **VALIDATES** JWT token contains valid user_id

## Entity 2: Task (Owned by Backend)

**Purpose**: Represents a todo task owned by a user. This is the primary entity managed by the backend API.

**Ownership**: Created and managed by this backend specification (Spec 2)

**SQLModel Schema**:
```python
from sqlmodel import SQLModel, Field, Relationship
from datetime import datetime
from typing import Optional

class Task(SQLModel, table=True):
    """
    Task model representing a user's todo item.
    Each task belongs to exactly one user.
    """
    __tablename__ = "tasks"

    # Primary Key
    id: Optional[int] = Field(
        default=None,
        primary_key=True,
        description="Auto-incrementing task identifier"
    )

    # Foreign Key to User
    user_id: str = Field(
        foreign_key="users.id",
        index=True,
        description="UUID of task owner from JWT token"
    )

    # Task Data
    title: str = Field(
        max_length=500,
        description="Task description/title"
    )

    completed: bool = Field(
        default=False,
        description="Whether task is marked complete"
    )

    # Timestamps
    created_at: datetime = Field(
        default_factory=datetime.utcnow,
        description="Task creation timestamp"
    )

    updated_at: datetime = Field(
        default_factory=datetime.utcnow,
        description="Last modification timestamp"
    )

    # Relationship (optional, for ORM navigation)
    # user: Optional[User] = Relationship(back_populates="tasks")
```

**Database Table**:
```sql
CREATE TABLE tasks (
    id SERIAL PRIMARY KEY,
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    title VARCHAR(500) NOT NULL,
    completed BOOLEAN NOT NULL DEFAULT FALSE,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- Indexes for query performance
CREATE INDEX idx_tasks_user_id ON tasks(user_id);
CREATE INDEX idx_tasks_user_created ON tasks(user_id, created_at DESC);

-- Trigger to auto-update updated_at timestamp
CREATE OR REPLACE FUNCTION update_updated_at_column()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = CURRENT_TIMESTAMP;
    RETURN NEW;
END;
$$ language 'plpgsql';

CREATE TRIGGER update_tasks_updated_at BEFORE UPDATE ON tasks
FOR EACH ROW EXECUTE FUNCTION update_updated_at_column();
```

**Attributes**:
- `id` (SERIAL/INTEGER): Auto-incrementing primary key, unique per task
- `user_id` (UUID): Foreign key to `users.id`, identifies task owner
- `title` (VARCHAR(500)): Task description, required field
- `completed` (BOOLEAN): Completion status, defaults to `false`
- `created_at` (TIMESTAMP): Task creation time, auto-set
- `updated_at` (TIMESTAMP): Last modification time, auto-updated on changes

**Constraints**:
- `PRIMARY KEY (id)`: Ensures unique task identifiers
- `FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE`: Referential integrity, cascade delete when user removed
- `NOT NULL` on title, user_id: Required fields for valid task
- `DEFAULT FALSE` on completed: Tasks start incomplete

**Indexes**:
- `idx_tasks_user_id`: Fast filtering by user_id (used in all queries)
- `idx_tasks_user_created`: Composite index for sorted task lists per user

**Relationships**:
- **Belongs To**: Each task belongs to exactly one user
- **User Isolation**: Queries MUST filter by `user_id = {authenticated_user.id}`

## Query Patterns

### User Isolation (Applied to ALL Queries)

**Critical Security Rule**: Every database query MUST filter by authenticated user_id from JWT token.

```python
from sqlmodel import select, Session
from fastapi import Depends

async def get_user_tasks(
    user_id: str,  # From URL
    authenticated_user_id: str,  # From JWT token
    session: Session = Depends(get_session)
):
    # CRITICAL: Validate user_id matches JWT
    if user_id != authenticated_user_id:
        raise HTTPException(status_code=403, detail="Forbidden")

    # Query filtered by authenticated user
    statement = select(Task).where(Task.user_id == authenticated_user_id)
    tasks = session.exec(statement).all()
    return tasks
```

### Common Query Patterns

**List all tasks for user**:
```python
statement = select(Task).where(Task.user_id == user_id).order_by(Task.created_at.desc())
```

**Get single task with ownership check**:
```python
statement = select(Task).where(
    Task.id == task_id,
    Task.user_id == user_id  # Ownership check
)
task = session.exec(statement).first()
if not task:
    raise HTTPException(status_code=404, detail="Task not found")
```

**Create task with user ownership**:
```python
task = Task(
    user_id=authenticated_user_id,  # From JWT
    title=data.title,
    completed=data.completed
)
session.add(task)
session.commit()
session.refresh(task)
```

**Update task with ownership check**:
```python
statement = select(Task).where(
    Task.id == task_id,
    Task.user_id == user_id
)

task.title = data.title

```

**Delete task with ownership check**:

## Data Validation Rules

| Field | Validation | Error Response |
|-------|------------|----------------|
| title | Required, 1-500 chars | 400 Bad Request: "Title is required" |
| completed | Boolean (true/false) | 400 Bad Request: "Completed must be boolean" |
| user_id | UUID format, exists in users table | 403 Forbidden: "Invalid user" |
| task_id | Integer, exists in tasks table for user | 404 Not Found: "Task not found" |

## Database Constraints Summary

| Constraint Type | Column | Rule | Enforcement |
|----------------|--------|------|-------------|
| Primary Key | tasks.id | Unique, auto-increment | Database + SQLModel |
| Foreign Key | tasks.user_id → users.id | Must reference valid user | Database CASCADE |
| NOT NULL | title, user_id, completed | Cannot be null | Database + Pydantic |
| DEFAULT | completed | Defaults to FALSE | Database + SQLModel |
| INDEX | user_id | Fast filtering | Database |
| INDEX | (user_id, created_at) | Sorted queries | Database |
| UNIQUE | None | Multiple tasks can have same title | N/A |

## Testing Data Model

**Test Cases for Data Integrity**:

1. **Foreign Key Enforcement**: Attempt to create task with non-existent user_id → Should fail
2. **NOT NULL Validation**: Attempt to create task without title → Should fail (400)
3. **CASCADE Delete**: Delete user → All their tasks should be deleted automatically
4. **Default Value**: Create task without completed field → Should default to FALSE
5. **Auto-Increment ID**: Create multiple tasks → Each gets unique sequential ID
6. **Timestamp Auto-Update**: Update task title → updated_at should change, created_at stays same

## Performance Considerations

**Index Usage**:
- `idx_tasks_user_id`: Used in ALL queries (user isolation filter)
- `idx_tasks_user_created`: Used when listing tasks sorted by creation time
- No full table scans expected (all queries filter by indexed user_id)

**Query Complexity**: O(log n) for indexed lookups, O(n) for user's task list (n = user's task count, not total tasks)

**Scalability**: Partitioning by user_id possible if single user exceeds millions of tasks
