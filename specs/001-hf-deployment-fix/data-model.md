# Data Model: Deployment Workflow State

**Feature**: 001-hf-deployment-fix
**Date**: 2026-02-10
**Purpose**: Document the data entities and state transitions in the GitHub Actions deployment workflow

## Overview

This deployment workflow is stateless infrastructure automation. Unlike application features with persistent entities, this workflow processes ephemeral state that exists only during workflow execution. The "entities" here represent workflow inputs, intermediate state, and outputs.

## Entity 1: Workflow Configuration

**Description**: Static configuration data required for the deployment workflow to execute.

**Attributes:**
- `HF_TOKEN` (secret, string, required): Hugging Face API token with write access to target Space
- `HF_SPACE_REPO` (string, required): Hugging Face Space repository URL (e.g., `https://huggingface.co/spaces/USER/SPACE`)
- `BACKEND_DIR` (string, required): Path to backend directory in GitHub repository (e.g., `backend/`)
- `PYTHON_VERSION` (string, required): Python version for CLI installation (e.g., `3.11`)
- `GIT_USER_NAME` (string, optional): Git commit author name (default: `github-actions[bot]`)
- `GIT_USER_EMAIL` (string, optional): Git commit author email (default: `github-actions[bot]@users.noreply.github.com`)

**Validation Rules:**
- `HF_TOKEN` must not be empty or null
- `HF_TOKEN` must have write permissions to `HF_SPACE_REPO`
- `HF_SPACE_REPO` must be valid HTTPS URL matching pattern `https://huggingface.co/spaces/{org}/{space}`
- `BACKEND_DIR` must exist in repository
- `PYTHON_VERSION` must be supported by GitHub Actions (3.8+)

**Source:**
- GitHub repository secrets (HF_TOKEN)
- Workflow YAML file (all other attributes)

**Lifecycle:**
- Created: When workflow is triggered
- Used: Throughout all workflow steps
- Destroyed: When workflow completes

## Entity 2: Workflow Execution State

**Description**: Runtime state tracking the progress and status of each workflow step.

**Attributes:**
- `step_name` (string, required): Name of current step (e.g., "Install CLI", "Authenticate")
- `step_status` (enum, required): Status of step - `pending`, `running`, `success`, `failure`
- `step_start_time` (timestamp, required): When step started execution
- `step_end_time` (timestamp, optional): When step completed (null if still running)
- `step_output` (string, optional): Command output or error message
- `exit_code` (integer, optional): Process exit code (0 = success, non-zero = failure)

**State Transitions:**
```
pending → running → success (exit_code = 0)
                 → failure (exit_code ≠ 0)
```

**Validation Rules:**
- `step_status` must progress sequentially (no skipping states)
- `step_end_time` must be after `step_start_time`
- `exit_code` = 0 if and only if `step_status` = `success`
- Workflow stops on first `failure` status (fail-fast)

**Source:**
- GitHub Actions runner (automatically tracked)

**Lifecycle:**
- Created: When step begins execution
- Updated: As step progresses
- Destroyed: When workflow completes (persisted in logs)

---

## Entity 3: File Sync Manifest

**Description**: Metadata about files being synced from GitHub repository to Hugging Face Space.

**Attributes:**
- `source_path` (string, required): Path in GitHub repository (e.g., `backend/src/main.py`)
- `destination_path` (string, required): Path in Space repository (e.g., `src/main.py`)
- `file_hash` (string, required): SHA-256 hash of file content
- `file_size` (integer, required): File size in bytes
- `sync_action` (enum, required): Action to perform - `add`, `modify`, `delete`
- `sync_status` (enum, required): Status - `pending`, `synced`, `failed`

**Relationships:**
- One Workflow Execution has many File Sync Manifests (1:N)
- File Sync Manifest belongs to one Workflow Execution (N:1)

**Validation Rules:**
- `source_path` must exist in GitHub repository (for `add` and `modify` actions)
- `destination_path` must be relative path (no absolute paths)
- `file_hash` must match actual file content
- `sync_action` = `delete` if file exists in destination but not in source
- `sync_action` = `add` if file exists in source but not in destination
- `sync_action` = `modify` if file exists in both but hashes differ

**Source:**
- Generated by rsync during file sync step

**Lifecycle:**
- Created: During file sync step (rsync comparison)
- Used: For git commit (staging changes)
- Destroyed: After git push completes

---

## Entity 4: Git Commit Metadata

**Description**: Metadata for the git commit created during deployment.

**Attributes:**
- `commit_hash` (string, required): SHA-1 hash of commit (e.g., `a1b2c3d4...`)
- `commit_message` (string, required): Commit message (e.g., "Deploy backend from GitHub Actions")
- `commit_author` (string, required): Author name and email
- `commit_timestamp` (timestamp, required): When commit was created
- `parent_commit_hash` (string, required): Hash of previous commit in Space repository
- `changed_files_count` (integer, required): Number of files changed in commit
- `insertions` (integer, required): Lines added
- `deletions` (integer, required): Lines removed

**Relationships:**
- One Workflow Execution creates one Git Commit (1:1)
- One Git Commit contains many File Sync Manifests (1:N)

**Validation Rules:**
- `commit_hash` must be unique in Space repository
- `commit_message` must not be empty
- `commit_author` must match configured git user
- `parent_commit_hash` must exist in Space repository
- `changed_files_count` must equal number of File Sync Manifests

**Source:**
- Generated by git during commit step

**Lifecycle:**
- Created: During git commit step
- Used: For git push step
- Persisted: Permanently in Space repository git history

---

## Entity 5: Deployment Result

**Description**: Final outcome of the deployment workflow execution.

**Attributes:**
- `workflow_run_id` (string, required): GitHub Actions workflow run ID
- `workflow_status` (enum, required): Overall status - `success`, `failure`, `cancelled`
- `deployment_url` (string, optional): URL of deployed Space (e.g., `https://huggingface.co/spaces/USER/SPACE`)
- `commit_hash` (string, optional): Hash of deployed commit (null if deployment failed)
- `error_message` (string, optional): Error description if deployment failed
- `failed_step` (string, optional): Name of step that failed (null if success)
- `total_duration_seconds` (integer, required): Total workflow execution time
- `triggered_by` (string, required): GitHub username or event that triggered workflow

**Validation Rules:**
- `workflow_status` = `success` if and only if all steps succeeded
- `commit_hash` must be null if `workflow_status` = `failure`
- `error_message` must be null if `workflow_status` = `success`
- `failed_step` must be null if `workflow_status` = `success`
- `total_duration_seconds` must be positive integer

**Source:**
- Aggregated from all workflow steps by GitHub Actions

**Lifecycle:**
- Created: When workflow completes (success or failure)
- Persisted: In GitHub Actions logs and workflow run history
- Queryable: Via GitHub Actions API or UI

## State Transition Diagram

```
[Workflow Triggered]
        ↓
[Load Configuration] → Workflow Configuration entity created
        ↓
[Install CLI] → Execution State: pending → running → success/failure
        ↓
[Authenticate] → Execution State: pending → running → success/failure
        ↓
[Clone Space Repo] → Execution State: pending → running → success/failure
        ↓
[Sync Files] → File Sync Manifest entities created (one per file)
        ↓
[Commit Changes] → Git Commit Metadata entity created
        ↓
[Push to Space] → Execution State: pending → running → success/failure
        ↓
[Workflow Complete] → Deployment Result entity created
        ↓
[Cleanup] → All ephemeral entities destroyed (only logs persist)
```

## Data Flow

```
GitHub Repository (source)
        ↓
[Workflow Configuration] ← GitHub Secrets (HF_TOKEN)
        ↓
[CLI Installation] → huggingface_hub package
        ↓
[Authentication] → Git credential helper (ephemeral)
        ↓
[File Sync] → File Sync Manifest (rsync output)
        ↓
[Git Commit] → Git Commit Metadata
        ↓
[Git Push] → Hugging Face Space Repository (destination)
        ↓
[Space Rebuild] → Deployed Application
```

## Error States

### Authentication Failure
- **Trigger**: Invalid HF_TOKEN or insufficient permissions
- **State**: Execution State = `failure`, failed_step = "Authenticate"
- **Recovery**: Update HF_TOKEN in GitHub secrets, re-run workflow

### File Sync Failure
- **Trigger**: Backend directory not found or rsync error
- **State**: Execution State = `failure`, failed_step = "Sync Files"
- **Recovery**: Verify BACKEND_DIR path, check file permissions, re-run workflow

### Push Failure
- **Trigger**: Network timeout, Space repository locked, or merge conflict
- **State**: Execution State = `failure`, failed_step = "Push to Space"
- **Recovery**: Check Space repository status, resolve conflicts, re-run workflow

## Data Retention

- **Workflow Configuration**: Persisted in workflow YAML file (version controlled)
- **Execution State**: Persisted in GitHub Actions logs (90 days default retention)
- **File Sync Manifest**: Ephemeral (destroyed after workflow completes)
- **Git Commit Metadata**: Persisted permanently in Space repository git history
- **Deployment Result**: Persisted in GitHub Actions logs (90 days default retention)

## Security Considerations

- **HF_TOKEN**: Encrypted at rest in GitHub secrets, masked in logs, never persisted in workflow artifacts
- **Git Credentials**: Stored ephemerally in git credential helper, cleared after workflow completes
- **File Content**: Transmitted over HTTPS (encrypted in transit)
- **Commit Metadata**: Public in Space repository (no sensitive data in commit messages)

## Performance Characteristics

- **Workflow Configuration**: Loaded once at workflow start (negligible overhead)
- **Execution State**: Updated per step (7 steps × ~10ms = 70ms overhead)
- **File Sync Manifest**: Generated per file (100 files × ~5ms = 500ms overhead)
- **Git Commit Metadata**: Generated once (single commit, ~50ms overhead)
- **Deployment Result**: Generated once at workflow end (negligible overhead)

**Total Overhead**: ~620ms (well within 5-minute performance target)
